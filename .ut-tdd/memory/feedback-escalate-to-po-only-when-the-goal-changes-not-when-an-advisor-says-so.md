2026-07-31、PR #205 の設計判断を PO へ上げたところ**差し戻された**:
「裁定って何を？なんでもこっちによこすな。というか俺が決める必要があるものですらないだろそれ」。

## 何を間違えたか

顧問 2 名 (Fable / Sol) が**同じ結論 (A 系)** に収束していた。割れていたのは「PO 裁定の要否」だけで、
Fable = 不要 / Sol = 必要。私は Sol の慎重側へ寄せて上げた。**これが誤り。**

論点は「review SLA の 3 段 (15/30/60 分) を verdict 1 段へ畳むか」だった。15/30/60 は PO が外部監査
経由で示した数値だが、**監査原文自身が「本質は無反応の検知であってレビュー内容を急がせることではない」
と目的を明示している**。3 段→1 段は**その目的を一切変えない実装判断**であり、PO の意思決定事項ではない。

## 判断基準 (今後これで切る)

**PO へ上げるのは「PO が示した目的そのものが変わる」ときだけ。**
目的が同じで手段だけ変わるなら**自分で決めて進める**。

- 上げる: 目的・優先順位・受け入れ基準・外部公開・不可逆な破壊が変わる。
- 上げない: 同じ目的をより正確に満たす方式選択、閾値の畳み込み、内部構造、可逆な PR 上の実装。

**顧問が「PO 裁定が要る」と言っても、それ自体は上げる理由にならない。** 顧問の役割は方式の当否であって、
どこまでが PO の権限かの線引きではない。上げる/上げないは自分で判定する。

**顧問 2 名が同じ結論に収束したら、それは決められる証拠であって上げる理由ではない。**
収束を「合意が取れたので承認をもらう」へ変換しない。
