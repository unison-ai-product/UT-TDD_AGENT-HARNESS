## 共通の fixture 規律 (rev 3)

- 正系の fixture (genuine な H / M / R) は **production の経路で生成する**。経路は `assemblePlanRevisionCommand` → `derivePlanRevisionDigests` → `TrackedReceiptRenderer.render` である。
  verifier 自身の再導出関数で fixture を作らない。作ると tautology になる。
  実データの golden として、PLAN-L7-742 r2〜r4 (spike で全値が確定済み。`SPIKE.md`) を 1 組以上含める。

  1 か所だけ壊した偽造は chain 検査で先に落ちるので、receipt digest 検査の oracle にならない。

## mutation 一覧 (S2 の mutation probe 用)

各 mutation は、どの occurrence を除いたかを probe 記録に明記する (dead な重複が mutant を吸収するのを防ぐ)。

1. R の receipt 検査を `R ≠ H` に戻す → 017-a。
2. actor を R 側の入力から取る → 018。
3. H の再導出を省く → 019。
4. M の再導出を省く、または字義どおりの base 式を使う → 020。
5. `commandPayloadDigest` を production 以外の key 順で組む → 021。
6. frontmatter を部分照合にする、または record_digest を再計算しない → 022。
7. fast-path 非適用の分岐を 1 つずつ外す → 023。
8. `sourceCommit` / `occurredAt` の導出を変える → 017-c / 017-d。
9. domain separator を v1 のまま、または `ledger` を preimage から外す → 016。
