# R05 / 0.5.0：安全なチケット配布・動的作業計画

状態：版割当の提案・未実装/未受入。元M：M3a。構想target：v4.0。
責任：Control Plane/U23 owner / security・QA。実名/代理/予算上限は正式採択時に設定。
関連移行：MIG-04, MIG-05, MIG-07, MIG-08, MIG-16, MIG-17, MIG-18。

## 1. 利用者がこの版で得るもの
予測と実際の配布を分離したまま、資源制約下で正規に分担・合流・回復できる。

## 2. 新しく対応する範囲
- 既存L4責務×path×依存から大中小原子のticketとadmissionをcompile。上流曖昧要求の全compileはR07。
- 採番予約・owner・path lease・操作lease・heartbeat・fence・takeoverを共通U23へ統合。
- deterministic ready queue、依存解放/critical path/aging/reviewer・CI容量を使う順序決定、event-driven再計画。
- 作用直前に最新依存成立・権限・予算・資源・leaseをCASで再確認。別PC/cloneでも一意。
- 実行環境の隔離・送信/秘密/証拠保護、typed attempt/終端/回復、三者分離、incidentと合流/refactor検査。

## 3. この版に入れないもの
- 本番BugBot、根拠不明の完了時刻、最適解を保証する高価なsolver。
- LLMが統括判断を代行、期限を理由に未承認依存を飛び越えること。

## 4. 何を入れ替え、何を残すか
| 旧方式 | 新方式 | 維持/境界 |
|---|---|---|
| 空いたactorへの逐次手渡し | 制約付きdispatchとactual queue | 手動発行は理由付き例外 |
| ローカル予約/放置worktree | canonical reservationとtakeover/GC | historical recordは保存 |
| 完了見込みに頼る先行着手 | actual readiness再検証 | 予測は権限も完了も作らない |

## 7. 有効化の順序
R04のshadow計画→dry-run→一つのproject/責務の自動dispatch→複数actor→別cloneへ。旧手配経路も共通admissionを通す。

## 8. 移行失敗とrollback
新規dispatchを止めactive leaseをdrainし、accepted recordと高水位点を保存。検証済みfallback scheduler/手動割当へ切替。leaseを二つ作る旧経路へ戻さない。

## 9. 旧経路をいつ止めるか
対象projectの未予約編集、独自queue、直merge、二重role/ownerの権限抜け道を停止。全native agent再編はR08。
