# R00 / 0.2.0-canary.1：現行プレリリース閉包

状態：版割当の提案・未実装/未受入。元M：M0。構想target：v4.0。
責任：release owner / runtime・Memory責務owner。実名/代理/予算上限は正式採択時に設定。
関連移行：MIG-06。

## 1. 利用者がこの版で得るもの
開発元を参照せず、clean Packのみで上流開発の基本運用を再現する。

## 2. 新しく対応する範囲
- #487の到達可能Bun撤去と、禁止detector/互換語彙の分類を成立させる。
- project identity、Memory/provider/session隔離、migration/quarantine、Pack-only parityを現行#424の範囲で閉じる。
- #418のPLAN/DB/doctor/review/merge gateとWindows/Linux再起動相当smokeを対象releaseへ束縛。

## 3. この版に入れないもの
- v4機能、JSON新体系、予測配布、BugBot、MPL切替を新しいM0依存にしない。
- 初回公開だけで#364のA/B・stable受入が完了したとしない。

## 4. 何を入れ替え、何を残すか
| 旧方式 | 新方式 | 維持/境界 |
|---|---|---|
| 旧Bun到達経路 | Node正式実行経路 | BAN検出器と履歴語彙は区別して保持 |
| worktreeローカルのroot解釈 | canonical project root | 他project隔離と移行失敗時の回復も受入 |

## 5. 着手と公開の条件
開発前提：現行M0の正式入力。公開前提：現行release gate。
開発前提の成立と、consumerへ新capabilityを有効化できる条件は別。必要な先行schema/安全性だけを早期sliceにし、未受入のwriteを先に許可しない。

| SL | 出力 | 検証 | 先行SL |
|---|---|---|---|
| SL-R00-01 Bun/Memory残務を現行契約で閉じる | 既存#487/#424・対応PLANを再読し、未実装と既対応を区別 | 現行回帰と正負oracle | 版前提 |
| SL-R00-02 clean releaseから再現 | source checkout削除後の両OS fixture | release identityに束縛した#418証拠 | SL-R00-01 |

## 7. 有効化の順序
現行MITのimmutable tag/assetを確定し、internal canary対象だけへ配布。公開したことと受入完了を別に記録。

## 8. 移行失敗とrollback
失敗したcanaryをstableへ昇格しない。旧正常generationへ復帰し、失敗releaseと履歴は残す。consumer stateは勝手に巻き戻さない。

## 9. 旧経路をいつ止めるか
到達可能Bun経路はこの版で除去。古いGit履歴・license・正当なBAN文字列は削除対象ではない。
