# R04 / 0.4.0：低コストCI・共有view・順序予測

状態：版割当の提案・未実装/未受入。元M：M2b。構想target：v4.0。
責任：CI/view/scheduling責務owner。実名/代理/予算上限は正式採択時に設定。
関連移行：MIG-09, MIG-10。

## 1. 利用者がこの版で得るもの
導入先のCI固定負担を下げ、何を先に実行すべきかを人間が根拠付きで見られる版にする。

## 2. 新しく対応する範囲
- consumer既存CIとUT追加分の責務inventory、verification plan、必要集合を照合するaggregate。
- 変更影響選択をfullとshadow比較し、成立するscopeだけ選択実行へ。月2,000分soft budget、runner時間/請求/保存/未取得を区別。
- 要求/要件/設計のxlsx等のspreadsheet view・依存図・ER・状態表示と、構造化正本への承認付き変更提案。
- read-only scheduler: hard依存・資源・review/CI/merge待ち、残工程、見積り幅から着手/合流順を提案。
- context/事故/実行時間の計測と限定比較を開始。計画計算は原則決定的でLLM常駐なし。

## 3. この版に入れないもの
- 予測だけでチケットをclaim/開始、lease発行、mergeする機能。
- 未証明のCI省略、同じlockfileだけを根拠とするPASS流用。
- 常駐server/有料security製品の必須化。

## 4. 何を入れ替え、何を残すか
| 旧方式 | 新方式 | 維持/境界 |
|---|---|---|
| 固定的な毎PR全量検査 | risk/影響に束縛した必要検証 | 対象不明はfull fallback |
| 手更新の進捗/図/シート | source identity付きgenerated view | narrative本文への自動逆書込みはしない |
| 経験による順序予想 | schedule proposal＋理由/不確実性 | 人間の判断権限は保持 |

## 7. 有効化の順序
新profile/selectorをshadow→opt-in→新規consumer推奨へ。既存consumerの切替は個別のplan/承認。schedulerはこの版では常にadvisory。

## 8. 移行失敗とrollback
selectorが不健全なら旧full profileへ戻す。viewは再生成。予測engineを停止しても旧通常工程は動く。費用増見込みは通知し、検査を黙って削らない。

## 9. 旧経路をいつ止めるか
移行済みscopeの手更新ビューと重複workflowを無効化。監査用旧成果物は保持。正式なsource回帰自体は無差別に削除しない。
