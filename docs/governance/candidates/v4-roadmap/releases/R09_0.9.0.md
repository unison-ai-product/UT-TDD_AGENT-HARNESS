# R09 / 0.9.0：実録対策・context縮退・予測校正

状態：版割当の提案・未実装/未受入。元M：M6。構想target：v4.0。
責任：adaptation/context owner / evaluation QA。実名/代理/予算上限は正式採択時に設定。
関連移行：MIG-12, MIG-13, MIG-19, MIG-20。

## 1. 利用者がこの版で得るもの
モデルが得意になった一般説明を減らし、必要な実トラブル対策へcontextを集中する。

## 2. 新しく対応する範囲
- judgementと後続結果のcalibration、CASE/SCENE/PATTERNと適用/失効/再検証の寿命管理。
- task/model/runtime別に現行packetと縮退packetを同条件・holdout比較し、効果がある範囲だけ適用。
- 機構化済み注意文・旧workaround・一般手順を条件付き化/退役し、必須契約/事実/安全制約は保持。
- schedulerの時間/修正/レビュー/費用予測を実績で校正し、unknown fallbackと計画変更コストを維持。
- project opt-inの改善exportとblind boundary、改善の人間向けdigest、可逆quarantine。

## 3. この版に入れないもの
- 全タスクでtoken削減必須、モデル新発売だけを根拠に短縮。
- 単一事故から全体policy自動生成、学習AIによる正解集合/権限の変更。
- ML精度や最適性の無根拠保証。

## 4. 何を入れ替え、何を残すか
| 旧方式 | 新方式 | 維持/境界 |
|---|---|---|
| 全件記憶・一般proseの常時注入 | 最小typed packetとon-demand retrieval | source/監査履歴は別に保持 |
| 注意書きの積み増し | 根因修理/guard/回帰/条件付き対策 | 重大局所修理を学習待ちにしない |
| 固定所要時間の並び替え | 根拠付き見積り幅と実績校正 | 未知は確定ETAにしない |

## 7. 有効化の順序
限定task×model×roleから有効化。直接の硬いgate昇格は正規設計/独立review/rollbackを経る。計測はR03/R04から蓄積済みのものを使う。

## 8. 移行失敗とrollback
profile/registryを検証済み版へ戻し、対象学習assetをquarantine。incident・calibration・失敗評価は保持。モデルの実revisionが不明なら既知profileへfallback。

## 9. 旧経路をいつ止めるか
証拠付きで旧重複prompt/skill/adapter/active archive参照を停止。発火回数0だけで安全策を削除しない。
