# R01 / 0.2.0-canary.2：MPL切替と管理責任の確定

状態：版割当の提案・未実装/未受入。元M：M1。構想target：v4.0。
責任：PO / 統括メンテナー / release owner。実名/代理/予算上限は正式採択時に設定。
関連移行：MIG-01, MIG-02, MIG-15, MIG-17, MIG-18。

## 1. 利用者がこの版で得るもの
UT本体をMPL-2.0へ切り替え、移行後の開発・公開責任を明確にする。

## 2. 新しく対応する範囲
- 権利処理できるUT本体のLICENSE・package表記・対象ファイル通知をMPL-2.0へ揃える。
- Packの該当コード、実配布versionのsource取得方法、第三者表示を整合。
- 開発元/consumer/AIの権限境界、任命・代理・公開・脆弱性受付の意味契約を確定。
- 構想v4をtargetとして採択する変更はライセンスPRとは分離。active capabilityと未実装を別に宣言する。

## 3. この版に入れないもの
- licenseキー・有料化・第三者コードの一律再ライセンス。
- 未実装のv4ルールを全資産へ即時強制。

## 4. 何を入れ替え、何を残すか
| 旧方式 | 新方式 | 維持/境界 |
|---|---|---|
| UT本体のMIT表示 | 対象コードのMPL-2.0表示 | 過去MIT tag/asset、必要な他者通知を保持 |
| 暗黙の管理兼務 | 責務・権限・代理の明示 | 実在しない人名・承認を補完しない |

## 5. 着手と公開の条件
開発前提：R00。公開前提：R00。
開発前提の成立と、consumerへ新capabilityを有効化できる条件は別。必要な先行schema/安全性だけを早期sliceにし、未受入のwriteを先に許可しない。

| SL | 出力 | 検証 | 先行SL |
|---|---|---|---|
| SL-R01-01 権利/適用境界の棚卸し | 著作権・コピー・依存・生成物の一覧、除外と根拠 | 権利判断と対象集合 | 版前提 |
| SL-R01-02 ライセンス整合切替 | 本体/Pack/license metadataの一括整合 | 表示/対象source取得の確認 | SL-R01-01 |
| SL-R01-03 管理とtarget authority採択 | 寄稿・公開・例外・supported範囲、#517差分 | 採択recordと旧新参照表 | SL-R01-02 |

## 7. 有効化の順序
版番号canary.2は本案。実際の発番時に衝突を調べる。ライセンス変更は機能の互換修正と別の公開説明を付け、既存consumerへ無承認適用しない。

## 8. 移行失敗とrollback
ライセンス切替の撤回とruntime rollbackは別。公開済みの許諾を巻き戻す操作はしない。機能失敗なら旧正常generationを指定し、各版の条件を維持。

## 9. 旧経路をいつ止めるか
現行配布の誤ったMIT表示は除去するが履歴は保存。MPLを理由に一般的な依存コンプライアンスengineを先行増築しない。
