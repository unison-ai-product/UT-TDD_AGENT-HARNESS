# R07 / 0.7.0：上流要求・PoC・再compile

状態：版割当の提案・未実装/未受入。元M：M4。構想target：v4.0。
責任：requirements/design owner / compiler owner。実名/代理/予算上限は正式採択時に設定。
関連移行：MIG-03, MIG-04, MIG-10, MIG-14。

## 1. 利用者がこの版で得るもの
上流の曖昧さを人間が判断し、変更が必要な下流だけを再構成する。

## 2. 新しく対応する範囲
- intake→append-only discovery→typed IR→人間freeze。provisional/frozenを要求単位で保持。
- PoC scope/budget/exit oracleとS4、screen inventory/fixture/異常系/finding/深度profile/独立Goldを実装。
- L3/L5製本、L4責務×依存→L5以下ticket、契約改訂→backflow dedupe→影響下fence→再compile。
- 対象active PLAN frontmatter/Reverse状態の新正本への移行を閉じ、過去記録のreaderは保持。
- schedulerに新規/無効化/変更の差分と不確実性を渡し、下流計画だけ更新。

## 3. この版に入れないもの
- AIによるfreeze・未知値補完、モック画像を正本にすること。
- 既存の確定要求を一括provisionalへ戻すこと。
- すべての歴史文書を新形式に変換すること。

## 4. 何を入れ替え、何を残すか
| 旧方式 | 新方式 | 維持/境界 |
|---|---|---|
| proseの質問/暫定判断 | 根拠付きdiscovery/decision record | 人間の自由文入力は維持 |
| レーン別の重複Reverse | 契約単位のbackflow集約と生成文書 | 採択済みnarrativeの人間編集は維持 |
| 手作業で全ticket書換え | 影響差分の再compile | 無関係な仕事を無効化しない |

## 7. 有効化の順序
UT自身の限定scope→承認されたconsumerの一工程→上流全体。旧proseは共通admission経由の入力として残し、二重確定はさせない。

## 8. 移行失敗とrollback
新規compileを停止。確定済み決定・source/旧新ID対応・eventを保持し、互換reader上で人間判断へ戻す。新版のfreezeを消して旧状態へ戻さない。

## 9. 旧経路をいつ止めるか
対象active scopeのprose-only状態writer、個別再発行台帳を停止。歴史文書はarchive/read-onlyとして継続。
